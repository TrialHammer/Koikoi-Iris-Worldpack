# Koikoi Iris 自定义群系注册键名表

本表记录 **实际由 Iris `customDerivitives` 注册到 Minecraft 群系注册表的自定义群系**，不是包内全部 403 个 Iris 群系定义的路径列表。当前 Koikoi 维度包含 **145 个客户端翻译键**，对应 **149 个内容寻址的实际注册资源**。

Iris 为每个自定义衍生项注册一个客户端别名 `iris:koikoi/<customBiomeId>`；实例中用于显示和翻译的键为 `iris.biome.koikoi/<customBiomeId>`。资源包可在 `assets/iris/lang/zh_cn.json` 中直接覆盖，例如：

```json
{
  "iris.biome.koikoi/tropical_plains": "热带平原"
}
```

当前 Iris 版本实际写入 Minecraft 注册表的资源键使用内容寻址形式 `iris:biomes/<sha256>`。表中的 `registryResources` 是 Koikoi 当前活跃生成 epoch 的实际资源；通常只需要翻译 `translationKey`。

注意：仅有 `derivative` 或 `vanillaDerivative` 的 Iris 群系不会因此获得 `iris.biome.*` 键；必须在定义中存在 `customDerivitives`。例如 Koikoi 的 `dappled/lake` 使用原版斑驳森林身份，但不单独注册一个 `iris.biome.koikoi/dappled_lake`。

## 资源包与数据包使用说明

资源包本地化使用 `translationKey`，文件位置通常为 `assets/iris/lang/zh_cn.json`。同一原版衍生身份下的多个 Iris 地形可能共享一个客户端翻译键，因为 `customBiomeId` 才是 Iris 注册显示名称的来源。

数据包开发时，如果目标是原版兼容分类，应根据 Iris 群系定义中的 `vanillaDerivative` 或 Minecraft 群系标签处理；如果必须针对 Iris 生成的注册资源，则使用表中的 `registryResources`，并注意这些资源是内容寻址键，随自定义群系定义内容变化。
